# OTKTER CMS

[Русский](./README.md) | [English](./README.en.md)

Система управления контентом сайта творческого объединения **«Открытая Территория»**.

Проект разрабатывается как полноценное fullstack-приложение с акцентом на архитектуру, проектирование предметной области, качество кода, тестирование и production-практики.

## О проекте

**OTKTER CMS** — административная система для управления контентом сайта «Открытая Территория».

CMS предназначена для управления:

- проектами;
- услугами;
- людьми;
- категориями;
- медиафайлами;
- дополнительной информацией;
- состоянием публикации контента.

Помимо решения прикладной задачи, проект используется для глубокого изучения современной fullstack- и backend-разработки: от анализа предметной области и проектирования базы данных до тестирования, контейнеризации и развертывания приложения.

## Архитектура

Проект организован как **монорепозиторий** и содержит два основных приложения:

```text
otkter-cms/
│
├── apps/
│   ├── admin/              # React-приложение
│   └── api/                # NestJS API
│
├── packages/               # Общие пакеты
├── docs/                   # Документация
├── docker/                 # Docker-конфигурация
│
├── README.md
├── README.en.md
├── package.json
├── pnpm-workspace.yaml
└── docker-compose.yml
```

Backend проектируется как **модульный монолит**.

```text
API
│
├── Auth
├── Projects
├── Services
├── People
├── Categories
├── Media
└── Common
```

Архитектура будет развиваться вместе с требованиями проекта. Дополнительные инфраструктурные компоненты добавляются только при наличии реальной задачи, которую они решают.

## Принципы разработки

### Domain-first

Проектирование начинается не с выбора таблиц или написания контроллеров, а с анализа предметной области.

```text
Предметная область
        ↓
Сценарии использования
        ↓
Доменная модель
        ↓
Модель данных
        ↓
API
        ↓
Архитектура
        ↓
Реализация
```

### Модульная архитектура

Backend разделяется на модули в соответствии с бизнес-областями системы. Каждый модуль имеет определенную ответственность и явные границы.

### Явные контракты

Взаимодействие frontend и backend строится вокруг явно определенных API-контрактов.

### Понимание базы данных

Prisma используется как ORM, но проектирование базы строится на понимании PostgreSQL, SQL, реляционной модели, ограничений, индексов и транзакций.

### Production-oriented development

Валидация, обработка ошибок, безопасность, тестирование, миграции, логирование и развертывание рассматриваются как полноценные части архитектуры приложения.

### Минимум неоправданной сложности

Redis, очереди сообщений, брокеры, микросервисы и другие инфраструктурные компоненты добавляются только при появлении задачи, для которой они действительно необходимы.

## Локальный запуск

Инструкции по локальному запуску будут добавляться по мере появления соответствующих компонентов проекта.

В дальнейшем весь development environment можно будет запускать через:

```bash
docker compose up
```

Для локальной разработки приложений:

```bash
pnpm install
pnpm dev
```
