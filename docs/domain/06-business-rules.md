# Бизнес-правила и ограничения

## Общие

- Нельзя опубликовать сущность без обязательных данных.
- Slug должен быть уникальным в рамках типа сущности.
- Опубликованную сущность можно редактировать.
- После изменения опубликованной сущности изменения должны отображаться на публичном сайте.
- `Project`, `Person` и `Product` не могут быть опубликованы без хотя бы одной категории.
- `Service` не может быть опубликован без иконки категории.
- Товар не может быть опубликован без цены.
- Для товара, требующего характеристик, публикация невозможна без хотя бы одного непустого списка характеристик.
- Созданный список характеристик не может быть пустым у опубликованного товара.

## Публикация и редактирование

Для root-сущностей используется поле `publication_status`.

Поддерживаются два состояния:

- `draft` — сущность не отображается на публичном сайте и может содержать неполные данные;
- `published` — сущность доступна на публичном сайте.

Проверка обязательных для публикации данных выполняется при переходе из `draft` в `published`.

Опубликованную сущность можно редактировать.

После изменения опубликованной сущности изменения должны отображаться на публичном сайте.

## Удаление root-сущностей

Удалить можно только root-сущность в состоянии `draft`.

Если сущность находится в состоянии `published`, перед удалением её необходимо снять с публикации и вернуть в состояние `draft`.

Правило применяется к:

- `Project`;
- `Service`;
- `Person`;
- `Product`.

## Проект

### Основной проект

Поле `is_main` определяет отображение опубликованного проекта в секции «Проекты» на главной странице сайта.

- `is_main = true` — проект отображается на главной странице;
- `is_main = false` — проект не отображается на главной странице, но остаётся доступным на странице всех проектов при `publication_status = published`.

Значение `is_main` не влияет на публикацию проекта.

### Активность проекта

Поле `is_active` определяет бизнес-состояние проекта.

- `is_active = true` — проект действующий;
- `is_active = false` — проект завершён.

Завершённый проект не снимается с публикации автоматически.

Если `publication_status = published` и `is_active = false`, проект остаётся доступным на публичном сайте, но отображается в визуальном состоянии завершённого проекта и содержит соответствующую отметку на странице проекта.

Значение `is_active` не влияет на публикацию проекта.

### Отображение категорий

Поле `category_is_attention` определяет специальное визуальное состояние блока категорий проекта.

- `category_is_attention = false` — категории отображаются в обычном виде;
- `category_is_attention = true` — весь список категорий отображается в attention-состоянии, а перед списком выводится специальная иконка.

Признак применяется ко всему блоку категорий проекта и не является свойством отдельной категории.

Значение `category_is_attention` не влияет на публикацию проекта.

### Активные события проекта

У одного проекта может одновременно существовать несколько активных событий.

Флаг `is_active` определяется независимо для каждого события и не ограничивает количество других активных событий того же проекта.

## Услуга

### Иконка категории

`Service` не может быть опубликован без `category_icon_id`.

Иконка категории используется для отображения услуги в специальном слайдере на публичном сайте.

Черновик услуги может не иметь иконки категории.

Используемое в `category_icon_id` изображение нельзя удалить, пока на него ссылается `Service`.

## Товар

### Доступность товара для покупки

Поле `is_available` определяет возможность покупки товара.

- `is_available = true` — товар доступен для покупки;
- `is_available = false` — товар недоступен для покупки.

Значение `is_available` не влияет на публикацию товара.

Опубликованный товар с `is_available = false` продолжает отображаться на публичном сайте, но не может быть куплен.

### Списки характеристик товара

Поле `requires_characteristics` определяет обязательность наличия характеристик товара при публикации.

Если `requires_characteristics = true`, для публикации товара должен существовать хотя бы один `ProductCharacteristicList`, содержащий минимум один `ProductCharacteristic`.

Если `requires_characteristics = false`, товар может быть опубликован без списка характеристик.

Если `ProductCharacteristicList` создан независимо от значения `requires_characteristics`, при публикации товара он должен:

- иметь заполненный `title`;
- содержать минимум один `ProductCharacteristic`.

Черновик товара может содержать список характеристик без `title` и без элементов.

### Характеристики товара

Каждый `ProductCharacteristic` должен содержать хотя бы одно значение:

- `text`;
- `color`.

Допускается заполнение обоих полей одновременно.

Полностью пустой `ProductCharacteristic`, у которого одновременно отсутствуют и `text`, и `color`, недопустим.
